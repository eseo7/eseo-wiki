이메일 도메인으로
임직원 인증과 전용 패키지 노출을 제어합니다.

사용자가 마이페이지에서 회사 이메일 인증을 완료하면 임직원 상태가 활성화되고, 해당 도메인 또는 도메인 그룹에 매칭되는 패키지만 노출됩니다. 개발 스펙을 운영자가 이해할 수 있도록 화면, 정책, API, DB, 배치 흐름으로 재구성했습니다.

핵심 요약

이 시스템은 “회사 이메일 인증 → 임직원 상태 부여 → 전용 상품 노출”을 자동화하는 구조입니다.

PM / 운영자용 요약

1. 도메인과 그룹을 관리

관리자는 허용할 이메일 도메인을 등록하고, 도메인들을 그룹으로 묶습니다. 예: 파르나스, 관계사, 제휴사 등.

도메인 등록 그룹 관리 엑셀 다운로드

2. 회원이 이메일 인증

사용자가 마이페이지에서 회사 이메일을 인증하면 employee_status = 'Y'로 전환됩니다.

인증 완료 Redis 코드 검증 멤버십 동기화

3. 임직원 전용 패키지 노출

패키지에 도메인/그룹 조건이 있으면 임직원 전용으로 보고, 사용자 도메인 또는 그룹이 매칭될 때만 노출됩니다.

전용 상품 도메인 매칭 그룹 매칭
💡
기획 관점의 핵심 판단 기준 패키지에 tag_email_domain 또는 tag_email_domain_group 값이 하나라도 있으면 임직원 전용 패키지로 간주합니다. 두 값이 모두 비어 있으면 일반 사용자에게도 노출됩니다.

도메인 관리

임직원 인증에 사용할 회사 이메일 도메인을 등록하는 영역입니다. 도메인은 단순 문자열이 아니라 회사명, 회사 ID, 그룹 정보와 함께 관리됩니다.

운영 항목확인 내용주의사항
도메인parnas.co.kr 같은 이메일 뒷부분중복 등록 방지 필요
회사명사용자 화면/관리자 화면에 표시될 회사 설명도메인의 description 값
회사 IDOWS 예약 연동용 값수정 불가 정책 적용
그룹패키지 노출을 묶어서 제어하기 위한 분류도메인 등록 시 필수 연결

도메인 그룹 관리

여러 도메인을 하나의 그룹으로 묶어 패키지 노출 조건을 단순화합니다. 예를 들어 “파르나스 계열사” 그룹에 여러 회사 도메인을 넣으면 패키지 설정 시 그룹 하나만 선택해도 됩니다.

⚠️
삭제 제한 그룹에 소속된 도메인이 하나라도 있으면 그룹 삭제는 불가합니다. 먼저 도메인을 이동하거나 삭제해야 합니다.

회원 인증 상태 확인

회원 상세 또는 마이페이지 대시보드에서 임직원 인증 상태, 인증일, 만료일, 도메인, 그룹명을 확인합니다.

Y
임직원 인증 상태employee_status = Y이면 임직원 전용 패키지 접근 가능
N
미인증 또는 만료 상태employee_status = N이고 만료일이 있으면 만료 안내 alert 노출

패키지 노출 설정

패키지 등록/수정 시 허용 도메인 그룹 또는 허용 도메인을 선택하면 임직원 전용 패키지가 됩니다.

설정 상태노출 대상설명
도메인/그룹 모두 비어 있음전체 사용자일반 패키지
도메인만 선택해당 도메인 인증자정확한 회사 단위 제한
그룹만 선택해당 그룹 소속 도메인 인증자여러 회사를 묶어 제한
도메인 + 그룹 선택둘 중 하나 매칭되는 인증자OR 조건으로 노출

만료/삭제 영향

임직원 인증은 영구 권한이 아니며, 도메인 삭제나 인증 만료 시 자동으로 일반 회원 상태로 되돌아갑니다.

🗑️
도메인 삭제 해당 도메인으로 인증한 모든 회원이 미인증 상태로 변경됩니다.
⏰
1년 만료 매일 03:10 배치가 만료 대상을 찾아 employee_status = N으로 변경합니다.

인증 플로우

사용자가 마이페이지에서 이메일 인증을 요청하고, 인증 완료 후 임직원 권한을 받는 전체 흐름입니다.

사용자 인증 흐름
1
이메일 입력 사용자가 마이페이지에서 임직원 이메일을 입력하고 인증을 요청합니다.
2
도메인 확인 booking 서비스가 허용 도메인 목록과 중복 인증 여부를 확인합니다.
3
인증 코드 발송 6자리 코드를 생성하고 Redis에 저장한 뒤 이메일을 발송합니다.
4
코드 검증 사용자가 코드를 입력하면 Redis 값과 비교하고 도메인 매칭을 확인합니다.
5
임직원 전환 상태값을 Y로 변경하고 인증일/만료일/도메인 ID를 저장합니다.

상세 타임라인

A

인증 요청

POST /hub/api/membership/certi/request/email 호출 → 도메인 whitelist 확인 → 인증 코드 저장/발송

B

인증 확인

POST /hub/api/membership/certi/check/email 호출 → Redis 코드 검증 → 임직원 도메인 여부 판단

C

회원 상태 업데이트

parnas_membership_user.employee_status = 'Y', 인증일, 만료일, 도메인 ID, 이메일 저장

D

멤버십 서비스 동기화

/v1/membership/hub/member/register/employee 호출로 membership 원장에 임직원 상태 반영

E

토큰 발급

임직원 인증 완료 시 HUB_EMPLOYEE 권한 기준으로 JWT를 발급합니다.

패키지 노출 정책

패키지가 일반 상품인지 임직원 전용 상품인지 판단하고, 사용자의 도메인/그룹과 매칭해 노출 여부를 결정합니다.

상품 노출 규칙

일반 패키지

tag_email_domain과 tag_email_domain_group이 모두 비어 있으면 모든 사용자에게 노출됩니다.

전체 노출 비회원/일반회원/임직원

임직원 전용 패키지

두 필드 중 하나라도 값이 있으면 임직원 전용으로 처리합니다. 사용자는 인증 상태이고 만료 전이어야 합니다.

조건부 노출 employee_status = Y 만료 전

매칭 우선순위

단계판단 내용결과
1사용자의 employee_email_domain_id로 도메인 정보를 조회도메인 ID 확보
2도메인 정보에서 group_id 조회그룹 ID 확보
3-A패키지의 tag_email_domain에 사용자 도메인 ID가 포함되는지 확인포함되면 노출
3-B패키지의 tag_email_domain_group에 사용자 그룹 ID가 포함되는지 확인포함되면 노출
🔀
OR 조건 도메인 조건과 그룹 조건은 둘 중 하나만 매칭되어도 노출됩니다. 즉, 특정 회사만 열 수도 있고, 여러 회사를 묶은 그룹 단위로 열 수도 있습니다.

배치 · 삭제 · 동기화 운영

임직원 권한은 만료/삭제/변경 시 booking 서비스와 membership 서비스가 함께 정리되어야 합니다.

운영 영향도

만료 배치

매일 03:10에 employee_status = 'Y'이고 만료일이 지난 회원을 찾아 미인증 처리합니다.

  • Cron: 0 10 3 * * *
  • 대상: employee_expire_date <= 어제
  • ShedLock 적용

도메인 삭제

도메인이 삭제되면 해당 도메인으로 인증한 회원 전체를 미인증 상태로 변경합니다.

  • del_yn = 'Y'
  • 회원 인증 취소
  • membership 일괄 취소 API 호출

도메인 변경

회사 ID는 OWS 연동 값이므로 변경 불가입니다. 이메일 도메인 변경은 정책상 허용 여부를 명확히 해야 합니다.

  • 회사 ID 수정 불가
  • 도메인 변경 시 회원 이메일 목록 영향
  • 변경 자체 차단도 검토 가능

검수 체크리스트

화면/UX 확인

  • 마이페이지에 임직원 인증 상태, 인증일, 만료일이 명확히 보이는가?
  • 만료된 회원에게 만료 alert가 노출되는가?
  • 인증 이메일 발송 후 사용자가 다음 행동을 이해할 수 있는가?
  • 인증 실패 사유가 도메인 불일치/코드 불일치/만료 등으로 구분되는가?
  • 관리자 유저 상세에서 임직원 이력이 확인되는가?

운영 정책 확인

  • 회사 ID corporateId는 수정 불가로 막혀 있는가?
  • 도메인 삭제 시 인증 회원이 미인증 처리되는 영향 범위를 운영자가 인지할 수 있는가?
  • 그룹 삭제 시 소속 도메인이 있으면 삭제가 차단되는가?
  • 도메인 이메일 변경 정책이 확정되었는가? 변경 허용/차단 중 택일 필요
  • 엑셀 다운로드 항목이 운영자가 필요한 컬럼을 포함하는가?

패키지 검수

  • 도메인/그룹 값이 없으면 일반 패키지로 노출되는가?
  • 도메인만 설정한 패키지가 해당 도메인 인증자에게만 노출되는가?
  • 그룹만 설정한 패키지가 해당 그룹 소속 도메인 인증자에게 노출되는가?
  • 도메인과 그룹이 모두 설정된 경우 OR 조건으로 노출되는가?
  • 만료된 임직원에게 전용 패키지가 숨겨지는가?

시스템/연동 검수

  • booking DB와 membership DB의 employee 상태가 동기화되는가?
  • 로그인/토큰 리프레시 시 권한이 일관되게 반영되는가?
  • JWT에 도메인 정보가 들어가지 않는가?
  • 만료 배치가 매일 03:10에 중복 실행 없이 처리되는가?
  • 로그 테이블에 인증/취소/만료 이벤트가 기록되는가?

용어 정리

회의나 검수 중 헷갈리기 쉬운 용어를 기획자 관점으로 정리했습니다.

Glossary

도메인

이메일 주소의 @ 뒤 부분입니다. 예: company.com. 임직원 인증 가능 여부를 판단하는 기본 단위입니다.

도메인 그룹

여러 도메인을 묶은 분류입니다. 패키지 노출을 회사별이 아니라 그룹 단위로 제어할 때 사용합니다.

employee_status

회원이 현재 임직원으로 인정되는지 나타내는 핵심 상태값입니다. Y이면 임직원, N이면 일반 회원입니다.

Redis

이메일 인증 코드처럼 짧은 시간만 필요한 값을 임시 저장하는 저장소입니다.

JWT

로그인 후 사용자의 권한을 확인하기 위해 발급되는 토큰입니다. 이 스펙에서는 role만 사용하고 도메인 정보는 넣지 않습니다.

ShedLock

여러 서버에서 같은 배치가 동시에 실행되지 않도록 막아주는 분산락 도구입니다.
