비개발자용 개요

이 문서는 포털에서 CRS 권한 계정을 등록했는데도 사용자가 실제 접속 시 오류가 나는 경우, 추가로 확인해야 하는 시설별 노출 권한 매핑 업무를 설명합니다. 쉽게 말해 “사용자 그룹 권한은 줬지만, CRS에서 어떤 호텔 범위를 볼 수 있는지 연결값이 빠진 경우”를 처리하는 문서입니다.

언제 필요한가?

신규 보안그룹을 만들고 그 그룹에 CRS 권한을 주는 경우

문제 증상

Admin 등록은 했지만 사용자가 CRS 접속 시 오류가 발생

핵심 조치

auth_group_id를 HOTEL_GROUP value와 매핑

문서 전체 분석 요약

상황해야 할 일PM 관점 확인
신규 보안그룹으로 회원 등록회원 PK, auth_group_id 확인 후 매핑 테이블 등록 여부 확인. 없으면 Insert어떤 호텔 범위를 노출해야 하는지 사전에 확정
기존 보안그룹에 신규 회원 추가일반적으로 사용자 등록/그룹 설정만 진행로그인 오류가 있으면 매핑 누락 여부 확인

핵심 요약

CRS 권한은 단순히 “메뉴 권한”만으로 끝나지 않습니다. 신규 보안그룹을 만들면 해당 그룹이 CRS에서 어느 호텔/브랜드 범위를 볼 수 있는지 ss_system.auth_group_custom_value_mapping 테이블에 추가로 연결해야 합니다.

운영자 매뉴얼 버전

신규 그룹인지 기존 그룹인지 먼저 구분

새로운 보안그룹을 만들었으면 추가 매핑이 필요할 가능성이 높습니다. 기존 보안그룹에 사람만 추가했다면 보통 추가 작업은 없습니다.

권한 요청 범위 확인

요청자가 루미오 전체 호텔, 나인트리 5개점, 인터컨티넨탈, 파르나스 제주 중 어떤 범위를 봐야 하는지 확인합니다.

사용자 PK와 보안그룹 ID 확인

개발자에게 system_user와 system_user_auth_group 테이블에서 사용자와 그룹 값을 확인하도록 요청합니다.

매핑 테이블 등록 여부 확인

auth_group_custom_value_mapping에 해당 auth_group_id가 HOTEL_GROUP으로 등록되어 있는지 확인합니다.

누락 시 Insert 후 로그인 테스트

매핑 정보가 없으면 value 기준에 맞게 Insert하고, 실제 사용자 계정으로 CRS 접속/조회 테스트를 진행합니다.

개발자 복사센터

개발자가 바로 복사할 수 있도록 테이블명, 조회 SQL, Insert 예시를 텍스트로 제공합니다. 실제 컬럼명/PK 조건은 운영 DB 구조에 맞게 확인 후 적용해야 합니다.

관련 테이블 목록
ss_system.system_user
ss_system.system_user_auth_group
ss_system.auth_group_custom_value_mapping
1. 회원 PK 확인 SQL 예시
SELECT id, user_id, user_name, email
FROM ss_system.system_user
WHERE user_id = '{사용자ID}'
   OR email = '{사용자이메일}';
2. 보안그룹 ID 확인 SQL 예시
SELECT system_user_id, auth_group_id
FROM ss_system.system_user_auth_group
WHERE system_user_id = {회원_PK};
3. 보안그룹 매핑 여부 확인 SQL 예시
SELECT *
FROM ss_system.auth_group_custom_value_mapping
WHERE auth_group_id = {auth_group_id}
  AND type = 'HOTEL_GROUP'
  AND deleted = false;
4. 매핑 정보 Insert SQL 예시
INSERT INTO ss_system.auth_group_custom_value_mapping
(auth_group_id, type, value, deleted)
VALUES
({auth_group_id}, 'HOTEL_GROUP', '{루미오|나인트리|인터컨티넨탈|파르나스}', false);

주의사항

메뉴 권한과 시설 노출 권한은 다릅니다
CRS 메뉴가 보이더라도 시설별 노출 매핑이 없으면 접속/조회 오류가 날 수 있습니다.
신규 보안그룹은 반드시 추가 확인
새 그룹은 기존 그룹과 달리 HOTEL_GROUP 매핑값이 없을 수 있습니다.
권한 과다 부여 주의
루미오는 전체 호텔 범위이므로 필요 이상으로 넓은 권한이 되지 않게 확인해야 합니다.
오류 발생 시 첫 확인 테이블
로그인 후 오류가 발생하면 auth_group_custom_value_mapping 테이블 누락 여부를 우선 확인합니다.
