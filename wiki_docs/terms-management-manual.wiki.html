Overview

비개발자용 개요

약관 관리는 단순히 문구를 바꾸는 일이 아니라, 법적 고지 문구를 서비스 화면에 정확히 노출시키는 운영 업무입니다.

무엇을?

약관 문구 변경

이용약관, 개인정보처리방침, 마케팅/광고성 동의, 취소·환불 규정 등 고객에게 노출되는 약관 내용을 변경합니다.

어디서?

CRS / Membership

현재 약관은 한 곳에서 통합 관리되지 않고 CRS와 Membership에 나뉘어 있습니다. 약관별 담당 시스템을 먼저 구분해야 합니다.

어떻게?

HTML + DB + 검수

워드 원문을 그대로 붙여넣지 않고 HTML 형태로 재생성한 뒤 신규 버전 등록, DB 반영, 다국어 등록, 실제 화면 검수를 진행합니다.

원문 문서는 개발/운영자가 보는 업무 메모에 가까워서, 실제 업무 흐름 기준으로 다시 정리했습니다.

문서가 말하는 핵심 구조
약관 변경은 파르나스가 변경 내용을 정리해 요청하고, H2O가 반영 일정과 최종 내용을 확인한 뒤 시스템에 반영하는 구조입니다.
운영상 가장 중요한 판단
변경 대상 약관이 CRS에 있는지 Membership에 있는지 먼저 확인해야 합니다. 시스템에 따라 즉시 반영 여부와 다국어 등록 방식이 다릅니다.
실수 위험이 큰 부분
워드 파일을 그대로 관리자 에디터에 붙여넣으면 CSS/에디터 반영 문제로 화면이 깨질 수 있어 HTML 코드를 별도로 생성해 DB에 넣는 방식으로 운영 중입니다.
구조적 개선 포인트
최종적으로는 Membership 한 곳에서 약관을 통합 관리하는 것이 맞지만, 요청 빈도가 낮아 현재의 이원화 구조를 유지하고 있습니다.

업무 흐름

변경 요청 접수

파르나스에서 변경할 약관명, 변경 내용, 적용 희망일, 적용 화면을 정리해 요청합니다.

반영 일정 및 최종본 확인

H2O는 반영 가능한 일정과 최종 반영 내용을 확인합니다. 이때 버전, 적용 대상, 노출 위치를 함께 확인해야 합니다.

관리 시스템 구분

해당 약관이 CRS에서 관리되는지, Membership에서 관리되는지 확인합니다. 시스템에 따라 등록/반영 방식이 다릅니다.

약관 HTML 재생성

워드 원문을 그대로 붙여넣지 않고, 서비스 화면에서 깨지지 않도록 HTML 형식으로 재생성합니다.

신규 버전 등록 및 DB 반영

업데이트 약관은 새 버전으로 등록하고, 생성한 HTML 코드를 새 버전 DB 정보에 반영합니다.

다국어 및 화면 검수

다국어 버전까지 등록한 뒤, 실제 푸터/회원가입/객실예약 결제 화면에서 정상 노출되는지 확인합니다.

약관 관리 위치

약관은 현재 두 개의 관리자 영역에서 나뉘어 관리됩니다.

CRS 관리자

CRS > 관리자 > 약관관리

  • 푸터 영역 약관 중심
  • 객실 예약 결제 내 취소/환불 동의 포함
  • 등록 즉시 새 버전으로 노출 반영

Membership 관리자

Membership > 멤버십 관리 > 멤버십 약관관리

  • 회원가입/마케팅/광고성 동의 중심
  • 당일 이후 날짜로만 등록 가능해 즉시 노출 이슈 존재
  • 즉시 반영이 필요하면 개발쪽 도움 필요
  • 다국어 등록 영역이 별도로 없어 DB 직접 반영 필요

현재 운영 방법

원문 문서의 운영 절차를 실제 수행 관점으로 풀어 정리했습니다.

1. 워드 원문 → HTML 변환

워드로 받은 약관 내용은 그대로 붙여넣어 사용할 수 없습니다. CSS와 에디터 반영 문제가 있어 HTML을 생성한 뒤 DB에 해당 코드를 직접 넣어 사용합니다.

2. 업데이트 약관은 새 버전 등록

기존 내용을 덮어쓰기보다 새 버전으로 등록하는 방식입니다. 버전 기준으로 언제 어떤 내용이 반영됐는지 추적할 수 있어야 합니다.

3. CRS 반영 방식

CRS는 등록 즉시 새로운 버전으로 노출됩니다. 다국어 버전도 동일하게 등록해야 하며, 번역본이 없으면 한국어로 대체 처리 중입니다.

4. Membership 반영 방식

Membership은 등록 시 당일 이후 날짜 등록만 가능해 바로 노출되지 않을 수 있습니다. 즉시 반영이 필요하면 개발쪽 보정이 필요하며, 다국어는 DB 직접 입력이 필요합니다.

Cautions

주의사항

서비스나 개발 구조를 모르는 사람이 가장 먼저 확인해야 할 리스크입니다.

!
워드 원문 직접 붙여넣기 금지에디터/CSS 반영 문제로 실제 화면이 의도와 다르게 보일 수 있습니다.
!
CRS와 Membership 혼동 금지관리 위치가 다르면 등록 방식, 반영 시점, 다국어 처리 방식도 달라집니다.
!
다국어 버전 누락 주의번역본이 없어도 각 언어 버전 등록이 필요할 수 있으며, 현재는 한국어 대체 처리 중입니다.
!
Membership 즉시 반영 이슈등록일 제약 때문에 바로 노출되지 않을 수 있어 개발 확인이 필요합니다.
!
노출 위치별 실화면 검수푸터, 회원가입, 객실예약 결제 화면에서 실제 표시 여부를 각각 확인해야 합니다.
!
버전/일정/최종본 기록법적 고지성 문서이므로 최종 반영본과 반영 일정을 남겨두는 것이 안전합니다.

Glossary

용어 설명

개발 문서에 자주 나오는 용어를 업무 관점으로 풀어 설명했습니다.

CRS
예약/객실 관련 정보를 관리하는 시스템 영역입니다. 이 문서에서는 푸터 약관과 객실 예약 결제 관련 약관이 포함됩니다.
Membership
회원가입, 리워즈 회원, 마케팅/광고성 동의 등 회원 관련 약관을 관리하는 영역입니다.
유형 코드
F01, F02, T004 같은 약관 식별 코드입니다. 같은 이름의 약관이 있어도 코드를 기준으로 정확히 구분합니다.
HTML
웹페이지에 표시되는 문서 형식입니다. 워드 내용을 화면에 맞게 표시하려면 HTML로 재가공해야 합니다.
DB 반영
관리자 화면 등록만으로 해결되지 않는 경우 데이터베이스에 HTML 코드나 다국어 값을 직접 넣는 작업을 의미합니다.
다국어 버전
한국어 외 언어 화면에서 보여줄 약관 버전입니다. 번역본이 없더라도 노출을 위해 한국어 대체 등록이 필요할 수 있습니다.
마수동
마케팅 정보 수신 동의의 줄임 표현으로 해석할 수 있습니다. 회원가입 또는 예약 결제 과정의 선택 동의 영역입니다.
광수동
광고성 정보 수신 동의의 줄임 표현으로 해석할 수 있습니다. 광고성 메시지 수신 동의와 관련됩니다.
노출 위치
고객이 실제로 약관을 보는 화면 위치입니다. 푸터, 회원가입, 객실예약 결제 등이 해당합니다.
FAQ

자주 발생하는 상황

운영 중 문의가 들어왔을 때 빠르게 판단할 수 있는 기준입니다.

약관을 등록했는데 화면에 바로 안 보여요.

CRS는 등록 즉시 노출되는 구조지만, Membership은 당일 이후 날짜 등록 제약 때문에 바로 노출되지 않을 수 있습니다. 이 경우 개발쪽에서 노출되도록 처리해야 합니다.

워드 파일을 관리자에 바로 붙여넣으면 안 되나요?

그대로 붙여넣으면 CSS나 에디터 스타일이 정상 반영되지 않을 수 있습니다. 화면 깨짐을 방지하려면 HTML을 생성한 뒤 DB에 넣는 방식으로 처리합니다.

번역본이 없는데 다국어는 어떻게 처리하나요?

원문 기준으로는 번역본이 따로 제공되지 않아 한국어로 대체 처리 중입니다. 단, 언어별 등록 자체는 누락되면 안 됩니다.

왜 약관을 두 시스템에서 나눠 관리하나요?

초기에는 CRS에서 관리했지만 마케팅 정보 수신 동의, 광고성 정보 수신 동의 업무가 추가되며 일부가 Membership으로 넘어간 상태입니다. 최종적으로는 한 곳에서 관리하는 구조가 더 바람직합니다.
