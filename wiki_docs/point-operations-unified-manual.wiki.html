비개발자용 개요

이 문서는 파르나스 리워즈의 포인트 업무를 적립 → 정산 → 취소 흐름으로 한 번에 이해하기 위한 통합 운영 매뉴얼입니다. 개발자가 보는 DB/프로시저 중심 문서를 PM/기획자 관점의 업무 흐름, 확인 포인트, 운영 리스크 중심으로 재구성했습니다.

포인트 적립

객실 체크아웃 또는 식음 결제 데이터를 기준으로 포인트가 생성됩니다.

포인트 정산

멤버십 데이터와 정산시스템 리포트가 맞는지 월별로 대사합니다.

포인트 취소

오적립/취소/예외 건은 정산 마감 전까지 취소 처리해야 합니다.

문서 전체 분석 요약

핵심 결론

포인트 업무의 핵심은 “무엇을 기준 금액으로 적립했는가”, “월말 정산 리포트와 실제 멤버십 내역이 일치하는가”, “취소 건이 정산 마감 전에 반영되었는가”입니다.

PM이 봐야 하는 이유

개발 용어가 많지만 실제 운영 이슈는 고객 포인트 누락, 과다 적립, 정산 불일치, 회계/SAP 반영 지연으로 나타납니다. PM은 요청 내용과 검수 기준을 명확히 잡아야 합니다.

정산월별 리포트와 실제 멤버십 내역 비교APOINT/BPOINT/CPOINT와 HISTORY LIST 일치 여부

운영자 매뉴얼 버전

포인트 적립 요청/문의 접수

고객번호, 주문번호, 호텔/업장, 객실/식음 구분, 결제일 또는 체크아웃일을 먼저 확보합니다.

적립 기준 확인

객실은 체크아웃 기준, 식음은 POS 영수증/회원 QR 결제 데이터 기준으로 적립 여부를 확인합니다.

월말 정산 대사

정산시스템 리포트와 멤버십 월간 내역을 비교해 차액이 있는 데이터를 찾습니다.

차이/오류 보정

누락, 중복, 잘못된 MEM_NO, 수기 등록 특성치 누락 등의 원인을 확인하고 보정 요청 또는 개발 처리합니다.

취소/마감 확인

취소 건은 정산 마감일 이전 처리 여부를 확인하고, 처리 후 리포트를 다시 뽑아 일치 여부를 검수합니다.

포인트 적립 이해하기

객실 적립

예약/결제가 완료되고 체크아웃 데이터가 생기면 구매정보를 기준으로 포인트 적립 배치가 수행됩니다. 적립액은 적립 대상 금액(product_price)에 등급별 적립률을 곱해 계산합니다.

식음 적립

현장 결제 시 회원 QR 등으로 회원 식별이 가능해야 하며, POS 영수증 데이터가 정산/멤버십 테이블로 넘어와 적립됩니다. 식음은 즉시 생성 데이터와 POS 영수증 기반 데이터가 함께 존재할 수 있어 중복/매칭 확인이 중요합니다.

적립 대상 금액 핵심

부가세와 봉사료는 포인트 적립 대상이 아니며, 쿠폰/바우처 할인과 포인트 사용 금액도 적립 대상에서 제외됩니다. 나인트리처럼 봉사료가 없는 케이스는 계산 기준이 달라질 수 있습니다.

포인트 정산 이해하기

APOINT

적립 포인트 정산 리포트입니다. 멤버십 적립 내역과 비교합니다.

BPOINT

사용 포인트 정산 리포트입니다. 식음 사용 내역과 CRS 예약 내역을 함께 봅니다.

CPOINT

만료 포인트 정산 리포트입니다. 소멸 대상 포인트와 비교합니다.

정산의 목적

정산시스템이 뽑은 리포트와 멤버십 시스템의 실제 포인트 내역이 완전히 일치하도록 맞추는 작업입니다. 차이가 있으면 누락 주문, 중복 POS 데이터, 수기 등록 특성치 누락, 예약/멤버십 API 누락 등을 확인합니다.

포인트 취소 이해하기

포인트 취소는 단순히 화면에서 취소 버튼을 누르는 업무가 아니라, 적립 내역/잔액/전표/정산까지 연결되는 민감한 운영 작업입니다.

정산 마감 전 처리
모든 운영 포인트 취소 건은 정산 마감일 이전에 처리되어야 합니다.
식음 포인트 예외
식음은 purchase_info가 2개 생기는 경우가 있어 일반 취소 프로시저로 안 될 수 있습니다.
처리 후 재검증
취소 프로시저 실행 후 결과와 잔액, 정산 리포트 반영 여부를 반드시 확인합니다.

주의사항 / 운영 이슈

부가세/봉사료 제외
포인트 적립 기준금액은 판매가 그대로가 아니라 세금/봉사료/할인/사용포인트 제외 후 기준입니다.
식음 POS 데이터 중복
식음은 결제 즉시 데이터와 POS 영수증 데이터가 함께 생길 수 있어 중복 여부를 봐야 합니다.
주류 정책 확인
주류는 원칙적으로 적립/할인 제외 대상이나 실제 POS 데이터 구분이 복잡해 협의 내용 확인이 필요합니다.
정산 기준일
메일로 받은 리포트는 전날 또는 특정 기준일까지의 내역일 수 있어 HISTORY LIST 조회 날짜를 맞춰야 합니다.
SAP 업로드 후 확인
최종 파일 업로드 후 SAP에 정상 반영되었는지 담당자 확인이 필요합니다.
