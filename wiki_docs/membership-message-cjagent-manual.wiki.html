Membership Message Delivery · CJAGENT

멤버십 메시지 발송
운영 인수인계

멤버십 서버에서 쌓인 SMS/MMS 데이터를 별도 CJAgent 서버가 읽고 전송하는 구조를 웹사이트형 운영 문서로 정리했습니다. 핵심은 발송 큐 테이블, 월별 이관 테이블, 인코딩 3종 세팅입니다.

1. 개요

CJAgent는 멤버십과 분리된 서버에서 동작하며, 멤버십 DB의 메시지 큐 데이터를 읽어 SMS 서버로 전송합니다.

Separate Agent Server
1

데이터 적재

멤버십 서버가 mms_msg, sms_msg 테이블에 발송 대상 데이터를 작성합니다.

2

Agent 읽기

CJAgent 서버가 큐 테이블을 읽어 메시지를 전송합니다. CJAgent는 멤버십과 별도 서버/도커 이미지에서 동작합니다.

3

월별 이관

전송된 데이터는 mms_msg_yyyyMM, sms_msg_yyyyMM 테이블로 옮겨 관리됩니다.

⚠️
운영 포인트

CJAgent가 로드될 때 mms_msg, sms_msg 테이블이 없으면 자동 생성합니다. 단, 운영 환경에서는 자동 생성에만 의존하지 말고 테이블 인코딩과 컬럼 상태를 먼저 점검하는 구성이 안전합니다.

2. 시스템 구조

멤버십 서버, CJAgent 서버, SMS 서버, 데이터베이스 테이블의 역할을 분리해서 보면 장애 원인 파악이 쉬워집니다.

Membership → CJAgent → SMS
구성요소역할확인 포인트장애 시 의심 지점

DB 테이블발송 대기 및 전송 완료 데이터 보관큐 테이블과 월별 이관 테이블 존재 여부, 인코딩테이블 없음, 권한 오류, 문자셋 불일치

4. 인코딩 이슈

한글 깨짐은 보통 DB 테이블, DB 연결 문자열, Agent 실행 인코딩 중 하나가 맞지 않을 때 발생합니다. 문서 기준으로 아래 3개 지점을 모두 맞춰야 합니다.

utf8 + UTF-8 + EUC-KR

① 테이블 인코딩

MMS_MSG 테이블을 utf8 / utf8_general_ci로 변환합니다.

DB Layer

② DB 연결 인코딩

JDBC URL에 characterEncoding=UTF-8을 명시합니다.

Connection Layer

③ 앱 실행 인코딩

CJAgent 실행 옵션에 -Dfile.encoding=EUC-KR을 적용합니다.

Runtime Layer

점검 기준

셋 중 하나라도 달라지면 한글이 깨질 수 있으므로, 장애 시 세팅을 묶음으로 확인합니다.

운영 점검
1) MMS_MSG 테이블 인코딩
ALTER TABLE MMS_MSG
  CONVERT TO CHARACTER SET utf8
  COLLATE utf8_general_ci;
2) cjagent.conf DB 연결 설정
# cjagent.conf 설정 중 일부
db_name=MYSQL
db_driver=com.mysql.cj.jdbc.Driver
db_url=jdbc:mysql://...:13306/membership?characterEncoding=UTF-8
db_sql=sql_mysql.sql
3) cjagentstart.sh 실행 인코딩
# cjagentstart.sh 파일 중 일부
# 실제 운영에서는 도커 환경 기준으로 변환해서 실행
nohup $JAVA_HOME/bin/java -Dfile.encoding=EUC-KR \
  -Djava.awt.headless=true \
  -jar $CJAGENT_HOME/$cjagent_list/cjagent.jar \
  $CJAGENT_HOME/$cjagent_list/conf/cjagent.conf > /dev/null &

5. 운영 체크리스트

발송 안 됨, 한글 깨짐, 데이터 미이관 같은 이슈가 발생했을 때 바로 확인할 항목입니다.

Troubleshooting

별도 서버의 도커 이미지/컨테이너가 정상 기동 중인지 확인
✓
DB 연결 문자열 확인
characterEncoding=UTF-8 누락 여부 확인
✓
실행 인코딩 확인
-Dfile.encoding=EUC-KR 옵션 적용 여부 확인
✓
월별 이관 확인
