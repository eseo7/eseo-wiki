회원가입 통합회원 CDP / CRS / CMS 동기화 운영매뉴얼 포함용

회원 가입부터 통합 전환까지
한 번에 보는 운영 프로세스

이 문서는 개발 원문에 있는 API, 상태값, DB 반영 순서를 운영자가 이해하기 쉬운 형태로 재구성한 매뉴얼입니다. 핵심은 회원의 출발점이 Web인지, Rewards인지, 신규 통합회원인지에 따라 userType과 integration_type이 달라지고, 이후 CDP·CRS·CMS 동기화 범위가 결정된다는 점입니다.

4개주요 API: join / login / register / update
3개핵심 시스템: Integration / CDP / Membership
2개외부 동기화: CRS / CMS
3종주요 회원 유형: Web / Rewards / Unified

1. 핵심 요약

비개발자 관점에서 먼저 봐야 할 결론입니다.

Executive Summary
운영 핵심 신규 가입은 바로 통합회원 형태로 생성됩니다. 일반 가입과 카카오 가입 모두 최종적으로 userType="U", integration_type="N" 상태가 됩니다.
전환 핵심 기존 Web 회원은 로그인 시 CDP 존재 여부에 따라 통합 가능 상태가 판단됩니다. CDP가 있으면 integration_type="U", 없으면 integration_type="T"로 분기됩니다.
병합 핵심 Web + Rewards 통합 등록 시 Web 계정은 Unified 계정으로 전환되고, 최종 로그인 ID/PW와 개인정보는 Rewards 기준으로 갱신됩니다.
동기화 핵심 회원 생성·수정 시 CDP, Membership, Integration 테이블을 반영하고, 조건에 따라 CRS와 CMS까지 동기화합니다.

2. 용어·상태값 정리

로그 분석, API 응답 확인, 장애 원인 파악 시 가장 먼저 확인해야 하는 값입니다.

3. 회원 상태 흐름

회원이 어느 경로로 가입/로그인했는지에 따라 최종 상태가 달라집니다.

State Flow
신규 Web 가입 초기 Web 회원 상태 W / N
로그인 & CDP 발견 통합 가능 여부 판단 W / U
Rewards와 통합 등록 Web + Rewards 병합 register
통합 회원 Unified 계정으로 전환 완료 U / N
정보 수정 CDP·Membership·CRS·CMS 동기화 update
신규 일반/카카오

가입 즉시 통합회원

신규 가입은 일반/카카오 모두 최종적으로 userType="U", integration_type="N"으로 생성됩니다.

Rewards 첫 로그인

Rewards 기준 진입

Rewards 첫 로그인 시 userType="R"로 진입할 수 있으며, 상황에 따라 integration_type="N" 또는 "U"가 됩니다.

기존 Web 회원

로그인 시 전환 판단

기존 Web 회원은 로그인 과정에서 CDP 존재 여부를 확인한 뒤 통합 가능/전환 가능 상태로 갱신됩니다.

5. 신규 회원 가입

일반 신규 회원 가입 시 내부 테이블 생성과 CRS 동기화까지 진행됩니다.

/integration/join

신규 회원 가입 API

POST /v1/membership/integration/join
Controller: IntegrationControllerService: createNewMemberForId()응답: IwsSignUpResponse
  1. 사용자 요청 수신 후 유효성 검사와 중복 체크를 수행합니다.
  2. CDP 고객 기본 레코드를 생성합니다. cdp.tb_cdp_customer_info
  3. CDP 커스텀 정보를 생성합니다. cdp.tb_cdp_user_custom_info
  4. 멤버십 회원 기본 정보를 생성합니다. membership.tb_membership_user_info
  5. 멤버십 발급, 등급, 쿠폰, 약관 정보를 순서대로 생성합니다.
  6. Integration 회원을 생성합니다. userType="U", integration_type="N"
  7. CRS 생성 동기화를 호출합니다. syncCreateInfoToCRS()

6. 신규 회원 가입: 카카오

기본 Flow는 일반 신규 가입과 동일하지만, 로그인 ID와 중복 체크 기준이 다릅니다.

Kakao Join
동일한 부분

가입 API와 생성 순서 동일

카카오 가입도 /integration/join을 사용하며 CDP, Membership, Integration 생성 및 CRS 동기화 흐름은 일반 가입과 같습니다.

다른 부분 1

loginId 처리

카카오 가입 시 loginId는 사용자가 입력한 ID가 아니라 membershipNo, 즉 멤버십 번호를 사용합니다.

다른 부분 2

channelId 중복 체크

카카오 ID인 channelId 기준 중복 체크가 추가됩니다. 카카오 연동 이슈 분석 시 반드시 확인해야 합니다.

7. Web 회원 로그인: 통합회원 전환 판단

기존 Web 회원이 로그인하면 통합 가능 여부가 판정되고, 그 결과가 integration_type으로 내려갑니다.

/integration/login

Web 회원 로그인 API

POST /v1/membership/integration/login
Service: commonLogin()응답: IwsLoginResponse
  1. Integration 테이블에서 loginId로 회원을 검색합니다.
  2. Integration 회원이 없으면 Rewards 회원 여부를 확인하고 필요한 경우 Integration 레코드를 생성합니다.
  3. 비밀번호를 검증합니다. Web 회원은 SHA256, Unified/Rewards 회원은 BCrypt를 사용합니다.
  4. 계정 잠금 상태와 블랙리스트 여부를 확인합니다.
  5. Web 회원은 CDP 존재 여부를 확인합니다. CDP가 있으면 integration_type="U", 없으면 integration_type="T"로 판단합니다.
  6. Integration 레코드와 마지막 로그인 시간을 갱신합니다.

8. 간편 로그인 / 카카오 로그인

CI와 채널 정보를 기준으로 Integration 또는 Rewards 회원을 찾고 로그인 상태를 반환합니다.

Simple Login

간편 로그인 요청값

channelId, memberCi, memberName, memberPhone
API: /integration/login대상: 카카오/간편 로그인
  1. loginCi로 Integration 회원을 먼저 조회합니다.
  2. Integration 회원이 없으면 Rewards에서 simpleId + memberCi로 조회합니다.
  3. Rewards 회원이 발견되면 Integration 레코드를 생성합니다.
  4. 잠금 상태와 블랙리스트를 체크합니다.
  5. Web 회원이 존재하면 integration_type을 업데이트합니다.
  6. 최종 회원 정보를 반환합니다.

9. 통합 회원 등록: Web + Rewards 병합

기존 Web 회원을 Rewards 회원과 연결해 통합회원으로 전환하는 핵심 프로세스입니다.

/integration/register

통합 등록 API

POST /v1/membership/integration/register
Service: setIntegrationMember()전환: W/U → U/N응답: IwsSignUpResponse
  1. webMemberId로 기존 Web 회원을 조회합니다.
  2. 대상 회원의 integration_type == "U" 여부를 검증합니다.
  3. rewardsMembershipId로 Rewards 회원을 조회합니다.
  4. Rewards 비밀번호 정보를 통합 ID/PW 기준으로 업데이트합니다. PW는 BCrypt로 인코딩합니다.
  5. Integration 레코드를 갱신합니다. userType: "W" → "U", integration_type: "U" → "N"
  6. 개인정보, systemKey, membershipNo는 Rewards 데이터를 기준으로 반영합니다.
  7. 약관 정보를 동기화하고 IwsSignUpResponse를 반환합니다.

10. 회원 정보 수정: 다중 시스템 동기화

회원 정보 수정은 Integration만 바꾸는 것이 아니라 CDP, Membership, CRS, CMS까지 영향 범위를 확인해야 합니다.

/integration/update

회원 정보 수정 API

POST /v1/membership/integration/update
Service: updateUserInfo()응답: Success
  1. Integration 회원을 조회합니다.
  2. Integration 테이블의 회원 정보를 업데이트합니다.
  3. systemKey가 있으면 Rewards 계정 보유자로 보고 CDP와 Membership 정보를 업데이트합니다.
  4. Rewards 계정 보유자는 CRS 수정 동기화를 호출합니다. syncUpdateInfoToCRS()
  5. cmsProfileId가 있으면 CMS 동기화를 호출합니다. syncUserInfoToCmsReq()
  6. 약관 정보를 업데이트합니다. membership.tb_membership_user_term_info

12. 운영자 확인 포인트

문의나 오류가 들어왔을 때 운영/기획자가 먼저 확인하면 좋은 항목입니다.

Operation Guide
가입 채널 확인일반 가입인지, 카카오 가입인지, 기존 Web 회원 로그인인지 먼저 구분합니다.
회원 유형 확인userType이 W, U, R 중 무엇인지 확인합니다.
통합 상태 확인integration_type이 N, U, T 중 무엇인지 확인합니다.
CDP 존재 여부 확인기존 Web 회원은 CDP 존재 여부에 따라 통합 가능/전환 가능 상태가 달라집니다.

CMS 동기화 확인cmsProfileId가 있는 회원은 CMS 동기화까지 확인합니다.

9. Integration 회원 생성 [integration.tb_integration_user_info]
   - userType: "U"
   - integration_type: "N"
   - loginId: 사용자가 제공한 ID
   - systemKey: membershipUserInfoId
    ↓
10. 🌐 CRS 동기화 → syncCreateInfoToCRS()
    ↓
[응답] IwsSignUpResponse

Web 회원 로그인 (통합회원으로 전환)
	/v1/membership/integration/login
======================================================================================
사용자 요청 (Web 회원 ID + 비밀번호)
    ↓
[IntegrationController] /integration/login
    ↓
[IntegrationService] commonLogin()
    ↓
1. Integration 테이블에서 loginId로 검색
    ↓
2. 없으면 → Rewards 회원 체크 → Integration 레코드 생성
    ↓
3. 비밀번호 검증
   - Web 회원: SHA256
   - Unified/Rewards: BCrypt
    ↓
4. 계정 잠금 상태 체크
    ↓
5. 블랙리스트 체크
    ↓
6. Web 회원의 경우 → CDP 존재 여부 확인
   - CDP 있음 → integration_type = "U" (통합 가능)
   - CDP 없음 → integration_type = "T" (전환 가능)
    ↓
7. Integration 레코드 업데이트
    ↓
8. 마지막 로그인 시간 갱신
    ↓
[응답] IwsLoginResponse with integration_type

통합 회원 등록 (Web + Rewards 병합)
	/v1/membership/integration/register
======================================================================================
사용자 요청
    ↓
[IntegrationController] /integration/register
    ↓
[IntegrationService] setIntegrationMember()
    ↓
1. webMemberId로 Web 회원 조회
    ↓
2. integration_type == "U" 검증
    ↓
3. rewardsMembershipId로 Rewards 회원 조회
    ↓
4. Rewards 비밀번호 업데이트
   - membershipId → unifiedId
   - membershipPw → unifiedPw (BCrypt 인코딩)
    ↓
5. Integration 레코드 업데이트:
   - userType: "W" → "U"
   - integration_type: "U" → "N"
   - loginId: unifiedId
   - loginPw: unifiedPw (BCrypt 인코딩)
   - systemKey: Rewards membershipUserInfoId
   - membershipNo: Rewards에서 가져옴
   - 모든 개인정보를 Rewards 데이터로 갱신
   - joinDate: 현재 시각 (통합 시점)
    ↓
6. 약관 동기화
    ↓
[응답] IwsSignUpResponse
